# lesson-player Specification

## Purpose
Play a Lesson as a deck of small Motion HTML Slides inside the client. Slides animate live in a sandbox, never as MP4. The player supports playback controls, preloading and offline use.

## Requirements

### Requirement: Slide format and manifest
Each Slide MUST be one self-contained Motion HTML document (HTML, CSS, JS) that plays a few seconds. A Lesson MUST have a Slide manifest listing Slides in order with `slide_id`, `duration_ms`, asset URLs and checkpoints. The Engine and API MUST validate Slide HTML before it is stored.

#### Scenario: Valid Lesson stored
- **WHEN** the Engine returns a Lesson
- **THEN** the API stores each Slide in object storage and writes the Slide manifest

#### Scenario: Invalid Slide HTML
- **WHEN** a Slide references an external network origin other than the asset origin
- **THEN** validation fails and the Slide is regenerated or the job fails

### Requirement: Sandboxed rendering
The client SHALL load one Slide at a time into `<iframe sandbox="allow-scripts">` with a strict CSP that blocks network access except the asset origin. Generated HTML MUST be treated as untrusted. The sandbox MUST NOT get `allow-same-origin`.

#### Scenario: Slide tries to reach the network
- **WHEN** a Slide script calls `fetch` to a third-party origin
- **THEN** the CSP blocks it and the player continues

#### Scenario: Slide tries to read app storage
- **WHEN** a Slide script reads parent storage or tokens
- **THEN** access is denied by the sandbox

### Requirement: Playback protocol and controls
The player SHALL control a Slide through a `postMessage` protocol with `play`, `pause`, `seek`, `ended` and `checkpoint`. The Learner MUST be able to pause, replay and step to the previous or next Slide.

#### Scenario: Pause and replay
- **WHEN** the Learner taps pause and then replay
- **THEN** the Slide pauses at the current time, then restarts from zero

#### Scenario: Slide ends
- **WHEN** a Slide posts `ended`
- **THEN** the player shows the next-step control and advances on tap or after auto-advance if enabled

### Requirement: Preload
The player SHALL preload the next Slide while the current Slide plays, so that advancing shows no blank frame on a normal connection.

#### Scenario: Normal connection
- **WHEN** Slide k plays
- **THEN** Slide k+1 HTML and assets are fetched and ready before Slide k ends

### Requirement: Offline cache
The client MUST cache a Lesson's manifest, Slides and assets once the Lesson has been opened, and MUST play cached Lessons offline. Progress made offline MUST sync when the connection returns, and the API MUST treat replays as idempotent.

#### Scenario: Offline replay
- **WHEN** the device is offline and the Learner opens a cached Lesson
- **THEN** all Slides play from the cache

#### Scenario: Sync on reconnect
- **WHEN** the connection returns
- **THEN** queued progress events are sent once each

### Requirement: Player analytics events
The client SHALL emit `lesson_started`, `slide_viewed`, `slide_replayed`, `slide_paused`, `lesson_completed` and `lesson_player_error` with properties from the `analytics` spec.

#### Scenario: Slide viewed
- **WHEN** a Slide reaches `ended`
- **THEN** `slide_viewed` is emitted with `lesson_id`, `slide_id`, `index`, `watch_ms` and `offline`

### Requirement: Slide data backup and retention
Slide HTML, assets and manifests MUST be stored in object storage with versioning enabled and included in the backup policy of the `data-backup` spec. Cached copies on devices are disposable and MUST NOT be the only copy.

#### Scenario: Slide object lost
- **WHEN** a Slide object is missing in storage
- **THEN** it can be restored from the previous version or regenerated by an operator job

### Requirement: Slide generation reliability
Slides MUST have Golden set cases (task `lesson_slides`) with deterministic checks: valid HTML, sandbox-safe, duration within bounds, no external origins. Scores MUST meet `evals/thresholds.toml`. The Engine MUST apply timeout and provider fallback as defined in `ai-reliability`.

#### Scenario: Unsafe output in eval
- **WHEN** a Golden set case yields a Slide with an external script
- **THEN** the deterministic check fails the case and the eval run fails if it is below threshold
