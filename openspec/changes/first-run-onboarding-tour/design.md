# Design

## Welcome and composition
An opaque rounded surface, green tactile actions and bundled Nunito sit above the token modal backdrop. Decorative rounded tiles suggest a small discovery. Heading: “Welcome to Duolify”; question: “What do you want to learn?”; introduction: “Start with something you're curious about. You can change your mind later.” A labelled topic input and “Explore this topic” lead to the existing brief, preview and outline with a learner-scoped, single-use session handoff. No background, goal or level questions are duplicated. “Help me decide” opens /profile/setup (the existing guided setup chat). “Try an example course” expands contract-backed choices and is absent for 404 or empty lists. Enrollment is free and idempotent; errors retain choices, retry and Skip. “Skip for now” closes welcome and starts the tour. Leaving into a chosen path defers the tour until Learn is next visited. Setup completion remains independent. Shared demo stays a read-only preview in creation, never an enrollment substitute.

## State machine and persistence
GET/PATCH /v1/me/onboarding reads/patches welcome_state and tour_state: pending, skipped, completed. New profiles default pending; all profiles existing at migration become completed to preserve returning learners. Partial patches preserve omitted state. Terminal states cannot return to pending; completed wins concurrent skipped writes. Welcome becomes completed after a successful handoff/enrollment, skipped on Skip; tour becomes completed on Done or skipped on Skip/Esc. Reads never complete anything. Settings replay ignores stored terminal tour state without resetting it. Local storage `duolify.onboarding.v1:<learner UUID>` holds only enum states and dirty fields; pending writes flush on Learn mount and online, merge monotonically with the server, and remain learner-scoped. Storage/network failures never block work. No free text is stored in this fallback. Topic handoff is ephemeral session storage and removed when consumed. Do not show on deep links, invite acceptance, SSO bridge or lessons; only / (Learn home) can launch it.

## Tour wireframes and final copy deck
The tooltip is an opaque bordered 24px rounded card, maximum 352px wide. Top row: small green discovery mark and step dots, with “Step {current} of {total}” text. Heading and description follow. Bottom: Back / Next (Done last); a separate always-reachable “Skip tour”. Each step answers what the feature does and why it helps. The spotlight surrounds the actual visible target with an 8px inset gap; an outlined triangular arrow joins card and target. These are explanatory steps, with page interaction blocked; none asks the learner to activate a target. Hidden/missing/disabled targets are omitted and the denominator reflects only present steps.

| Step enum | Spotlight / wireframe | Title | Tooltip text | Preferred arrow side |
| --- | --- | --- | --- | --- |
| path | Course heading on Learn, above its unit path | Your learning path | Your course is broken into small lessons. Follow the path at a pace that works for you. | top |
| next_lesson | First available lesson node | One small step | Start here when you're ready. Inside a lesson, Ask tutor can help you work through an idea. | top |
| credits | Visible Credits navigation link | A little help for your curiosity | Credits pay for AI help, like preparing lessons. Open your wallet to see your balance and any daily check-in available to you. | left on desktop, top on mobile |
| progress | Real daily-goal entry on Learn | Make room for a little learning | Your daily goal helps you build a habit. Check your XP and streak here, and choose a goal that fits your day. | top |
| notes | Quick notes navigation | Keep an idea close | Save quick notes as you learn. You'll find them here whenever you want to revisit an idea. | left on desktop, bottom on mobile |
| courses | Courses navigation | Follow your next curiosity | Come here to switch courses or create another one. Your progress stays with each course. | left on desktop, bottom on mobile |
| settings | Settings navigation, or More on mobile | Make yourself at home | Adjust how Duolify looks and feels in Settings. Choose Show me around there whenever you'd like this tour again. | left on desktop, bottom on mobile |

A learner with no course sees the five shell/progress steps; a learner with an available lesson sees seven. Tutor is explained in the next-lesson step, because there is no tutor control on Learn. The Credits step does not promise a grant before the parallel check-in feature is available.

## Positioning and accessibility
Use a small in-house implementation; no tour dependency. Query visible DOM anchors after home content settles. Scroll each into view with instant behavior. Measure target and card using getBoundingClientRect; prefer below, then above, then right/left as space permits, clamp within the visual viewport with 12px gutters. Arrow follows the clamped target centre and flips with placement. Observe target/card size, document scroll in capture phase, window resize and visualViewport scroll/resize (keyboard). No spotlight travel animation; reduced motion has no transition. Card is scrollable within the usable viewport so Skip is always reachable, even at large text sizes. Never render a spotlight for a detached or hidden target; move to a remaining visible step or finish.

Tour uses a modal dialog, focus enters its heading, Tab/Shift+Tab remain inside, Esc skips, Left/Right move Back/Next and Enter on the heading advances. All controls meet 44px. The target's accessible name is announced with the card and aria-describedby is attached/restored on the target. Focus is restored on close. The backdrop blocks pointer interaction outside the modal. Screen readers receive the complete sentence step count. Text uses opaque token surfaces and approved AA pairs in both themes; no text sits on the dim layer. Existing sheet behavior informs focus handling and scroll blocking.

## Data backup, analytics and reliability
Profile enum columns enter nightly encrypted Postgres backups (14 days), account/profile export, cascading erasure and restore tombstone replay. Register enum columns in the anonymizer; retain no onboarding history. Client fallback is expendable and never backed up. Events: onboarding_welcome_shown, onboarding_path_chosen(path topic/setup_chat/example/skip), onboarding_tour_started(source first_run/settings), onboarding_tour_step_viewed(step table enum), onboarding_tour_completed, onboarding_tour_skipped(at_step table enum). Use existing PostHog consent/UUID boundary and common properties; no topic, course title or transcript. Funnel joins sign_up to welcome/path/tour and existing first lesson events by learner UUID. No model behavior changes, no new golden cases needed; existing brief/setup AI fallbacks and eval gates remain authoritative.

## Test integration
Other suites can pre-complete through authenticated PATCH /v1/me/onboarding with both states completed; no production query flag disables onboarding. The shared mocked fixture performs this by default; new onboarding tests explicitly opt in. Deep-link tests do not encounter onboarding. Screenshots of each step are Playwright output attachments at 390px and 1280px and copied to the owner's requested scratchpad directory.
