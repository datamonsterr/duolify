# Design

Generate Android and Apple native projects with Tauri's `init --ci` in CI; generated projects are not source of truth. Apply required native permissions and signing configuration reproducibly after generation where Tauri configuration cannot express them. `Info.ios.plist` provides microphone usage text. Platform-specific configuration overlays add only the staging origins needed by native clients to the CSP, preserving ADR 0022's restrictions on scripts and frames. Existing `duolify://` deep links and mobile keyring plugin continue to support RFC 8252 sign-in.

Use Maestro's accessibility-layer automation for Android and iOS hybrid apps. Run a debug APK on API 34 x86_64 with KVM and an arm64 simulator app on macOS; preserve screenshots. Android also runs against the disposable e2e backend via 10.0.2.2, using its existing learner sign-in mechanism. iOS runs launch and landscape checks because the hosted macOS runner does not provide the Linux Docker backend. Both jobs are advisory and excluded from ci-ok until Android has three consecutive green runs.

A release preparation task validates a semver, synchronizes the three client versions, derives Android versionCode as major*10000+minor*100+patch, regenerates the changelog with git-cliff, and opens a PR. A main push detecting an untagged version or a manual dispatch builds release assets. A dry run uploads assets without tagging or publishing. The signed APK is verified against the expected certificate before publication; missing secrets or mismatched certificates fail closed. QR images are generated locally in CI and point at the stable latest APK and staging web app. iOS distribution is simulator-only; real-device/TestFlight distribution would require Apple enrollment and signing credentials.
