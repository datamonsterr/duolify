## Decisions
- **One authorization rule.** `BlockedEitherWay(ctx, q, a, b)` reads `learner_blocks` in both directions; `CanInteract` is its negation; `CanInvite(ctx, q, inviter, invitee)` adds the invitee's `course_invites_from`. `NotBlockedSQL(viewer, other)` returns the same predicate as a SQL fragment for list queries. Search, profile, friend link and send all use it, so there is one definition.
- **On-block registry.** `Service.OnBlock(fn)` registers `func(ctx, tx pgx.Tx, blocker, blocked string) error`. Callbacks run inside the block transaction after the friendship and requests are removed, in registration order. E15 registers one that cancels invites between the pair in **both** directions and any share references. A callback error rolls the block back (fail closed). No E15 tables exist yet; tests use a fake.
- **Race.** Block, send and accept all lock both `learners` rows in id order, then re-read state. Whichever commits first, the pair ends with a block and no friendship or pending request: send re-checks the block under the lock and accept finds its request deleted.
- **Neutral refusal.** A blocked send is treated exactly like an unknown recipient: it still counts toward caps and the daily send counter, then returns `request_unavailable`/`invite_unavailable`. The blocked learner sees only that the friendship disappeared; no event, request or analytics goes to them.
- **Block target visibility.** `POST /blocks` only accepts a target the actor can see (profile visibility, an existing friendship or a request between them); anything else returns `block_unavailable`, so it is not an existence probe.
- **Erasure.** The blocker's rows go with their account (`ON DELETE CASCADE`). Rows placed against a deleted learner are also deleted: a new account gets a new UUID, so an opaque hash of the old one could never match, and keeping it would only retain data. The spec's "MAY keep an opaque hash" is therefore not used.
- **Blocked list location.** The canvas has no blocked list; it sits on the Friends page (a "Blocked" tab/section) where block is offered, with unblock per row.
- **No unblock event.** The catalogue has none, so none is added.
