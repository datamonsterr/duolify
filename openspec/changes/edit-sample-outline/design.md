# Design

POST /v1/outline-drafts accepts brief_revision and outline (ordered units with globally unique opaque IDs, titles, ordered lessons and nonempty lesson goals). The brief must belong to the authenticated learner. GET collection by brief_revision returns the latest saved draft; GET /{id} reads it and DELETE /{id} erases it. Array position is the sole order and containment the sole parent. Limits: 10 units, 20 lessons/unit, 500 characters/title, 4000/goal, IDs at most 100 ASCII alphanumeric/hyphen/underscore characters. Empty outline/units may be saved while editing, but confirmation requires at least one unit and one lesson per unit. Blank titles/goals remain locally editable; saving invalid content fails without losing local edits.

PUT /{id} accepts expected_revision, outline and history. History is the last 50 pre-edit snapshots with focus IDs; both manual and later applied-chat changes use the same history contract. Persisting the current snapshot and bounded stack makes Undo survive reload, including across saves. A single row lock serializes saves/confirmation. Each save increments revision and clears confirmation. On stale save the API creates a separate recovery draft with the submitted snapshot/history, returning HTTP 409 with current and recovery. Neither branch is overwritten; the learner explicitly chooses the newer branch or their recovery copy. Invalid/unauthorized writes create no recovery row. Requests are bounded to 8 MiB and write rate limited. No implicit merge or retry overwrites newer content.

POST /{id}/confirm accepts expected_revision. Confirmation pins draft ID, revision, SHA-256 canonical outline hash and full snapshot; it performs no job, enrollment, model call or ledger write. GET /{id}/confirmed?expected_revision=N and ResolveConfirmed expose the exact current confirmed revision to future consumers; mismatch or a later save rejects it. Confirmation is a handoff only; course creation remains a separate explicit action in E2-02. E2-08 can validate proposals against GET head and use the same CAS save/history boundary. Device state is disposable after sync; unsaved in-memory edits survive failed saves and navigation controls preserve the mounted editor. A browser unload warning protects unsaved edits.

One learner-linked outline_drafts table stores head, history and optional confirmation. It cascades on account/brief deletion, is included in authenticated export, and enters nightly encrypted general Postgres backups retained 14 days. Brief expiry bounds draft lifetime to 30 days; existing nightly pre-backup brief purge cascades drafts. Restore replays account tombstones before serving. Fixtures populate and compare the complete row, including stable IDs/history/confirmation, and test deletion after restore.

Unselected recovery copies are marked is_recovery and excluded from the latest-head query, but remain owner-readable by ID and in exports. Choosing either branch explicitly CAS-saves that branch, increments its revision and promotes it to the latest resumable head; the other copy remains available. No reload silently selects an unapproved conflict copy.

Unsaved and failed-save work also has a disposable sessionStorage recovery copy, scoped to learner UUID and brief revision, with its original expected revision and history. It survives navigation/reload and is removed after successful synchronization; the mounted editor survives Back to preview. A stale recovered copy still goes through the server CAS/recovery flow. Device caches never enter backup and are never the recovery source for synchronized data.

Signing out clears the outline working copies. A session expiry can recover the same learner's unsaved work after reauthentication; another learner's cache key is never read.

Analytics uses existing ui_control_activated with surface=outline and control_id=outline_move|outline_rename|outline_remove|outline_add|outline_undo. The client wrapper sends only UUID/common properties and allowlisted control IDs, respecting opt-out. The API event allowlist already includes this event; its property allowlist gains surface. No title, goal, history, content hash or learner text is sent. No new domain/generation events. Model/eval/fallback boundaries remain unchanged because this feature never calls the engine.

Official API references checked before coding: React useState, PostgreSQL 18 explicit locking, pgxpool v5, Playwright assertions and MDN HTML Drag and Drop API.
