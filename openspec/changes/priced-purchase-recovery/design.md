# Defaults and boundaries

- Until the billing tickets supply verified provider integrations, web/desktop support an explicitly illustrative pending checkout. It never opens an external payment page, charges money, grants Credits or verifies a payment, even if a ledger entry has an unrelated purchase. Native platforms default to purchases unavailable; there is no external link or inferred regional exception.
- Persist pending orders and their original configured SKU, currency, amount, Credits and billing period. Illustrative orders always remain pending; cancellation is a local return state, not a claim about a provider payment.
- Only allow fixed internal return destinations, without query/hash/user text. Quote IDs must belong to the authenticated learner. Price changes require reselection against the current server version.
- Recovery preserves mounted work and stores only the order ID locally. Resume restores the action's review step; it never reserves, generates, enriches or sends. Notes/chat generation remain owned by their feature tickets.
- Financial orders join encrypted nightly dumps, 35-day snapshot retention and seven-year live retention. Export includes owned orders; account erasure and restore tombstones sever learner IDs and retain pseudonymous financial ownership. Local pending IDs are disposable and cleared with session data.
- Analytics uses the existing consent/UUID wrapper with a fixed field allowlist. No draft, note, prompt, return URL or free text enters events. No model changes: existing eval gates remain unchanged.
