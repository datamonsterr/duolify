# Design

The trusted API reads the current owned draft and checks the quoted draft ID/revision and request hash before reserving through E7-03. The engine receives stable IDs, that exact edited outline, untrusted request data and quote-derived bounds. Typed operations are applied deterministically, rejecting unknown/reused IDs, invalid parents/positions, empty titles/goals, contradictory operations and oversize results. Unmentioned nodes retain authored text and relative ordering.

A proposal ID is allocated before generation and keyed uniquely by quote ID. Reconnect reads that ID and never calls the provider again. A delivery transaction stores immutable operations/result before settlement; undelivered failures release Credits using canonical settlement. Pending records expose their owned request/base and status, with no diff until validation. An abandoned pending executor is never restarted by reconnect: after the original configured deadline its hold is released and its proposal fails, including a crash before reserve. Validated results resume settlement without another engine call. Provider attempts obey configured token, attempt, timeout and USD ceilings; the evaluated fallback is the second attempt. No model state persists.

Apply locks proposal and draft, requires the exact base revision, writes one revision and appends the old outline to the existing bounded 50-entry undo stack. Discard only records a decision. Undo restores the base only at the applied revision and records its decision once. Duplicate decisions return the saved result; opposing decisions and stale revisions return conflict and require explicit fresh review/re-quote. No decision calls the engine or wallet.

Draft-linked proposal/request/typed diff/decision data expires with its 30-day brief, purges before nightly backups, exports with the account and cascades on draft/account erasure. Nightly encrypted general backups retain 14 days and replay erasure tombstones. Quote, reservation and usage records retain existing separate financial retention/35-day backup policy; no learner text enters those snapshots or analytics.

Development config proposes 5 Credits and Daily free eligibility, explicitly approved=false. Settlement on valid proposal delivery even when discarded is pending E12-09 approval; production activation additionally requires E12-10. Deterministic offline recorded-provider cases cover every operation, manual edits, injection and bounded provider failure. Matching Postgres/HTTP fixtures cover insufficient balance, released failures, stale/duplicate decisions and free undo; live HF publication/promotion is deferred under ADR 0011.
