Generation checkpoints store validated lesson data and usage privately on the owned lesson_generations row. SettleWith commits product content, completion state and ledger together; transient storage errors leave the checkpoint for a worker retry. A crash without a checkpoint fails closed and releases customer Credits while retaining conservative operational cost. Cleanup intent survives ledger outages. Checkpoints are cleared at terminal states, exported only to the owner and erased through existing account/course cascades; populated full-row backup fixtures verify restore.

The existing GenerateRetryVariants RPC runs the shared provider executor and core validators, with at most one repair and API quote route, token, USD and deadline bounds. Missing pools in GenerateLesson call that path using only the remaining original quote budget. A failed paraphrase may use an existing validated pool; no valid initial pool means generation fails without charging. At answer time a missing/corrupt pool returns service unavailable without consuming the answer; exhaustion still recycles approved pool items for free (ADR 0011 clarification).

Analytics retain existing allowlisted events and identifiers only; checkpoint text, prompts, explanations and learner context never enter analytics. Offline recorded golden cases execute the production paraphrase processor and use E10 critical checks for semantic answer consistency, topic linkage, prompt distinction and the two-attempt ceiling. Live HF activation remains owner-gated by ADR 0011.
