# Cloudflare offload design

## Architecture

| Workstream | Cloudflare path | Hetzner authority | Fallback |
|---|---|---|---|
| W1 | Engine → Workers AI REST for opt-in TTS | River per-Slide work, quote and asset references, Engine synthesis contract | ElevenLabs within budget, then captions |
| W2 | Engine → authenticated AI Gateway → OpenRouter | Engine provider routing, checks, deadlines and budget | Direct OpenRouter under the same policy |
| W3 | Edge Worker → Hyperdrive → Access-protected Tunnel → private Postgres. Go verifies Turnstile. | Published snapshots, moderation, visibility and public HTTP contracts | Worker caches eligible Go public reads, or Go serves uncached |
| W4 | Edge Worker → per-session Durable Object. WebSocket, then SSE. | Go authorization, credit ledger, chat history/drafts, Engine fallback | Existing Go/Engine chat and deterministic Guided chat |

Postgres stays private on Hetzner with its backup and erasure coverage. Go, River, Redis and the ledger remain there so database writes, scheduling, idempotency and credit settlement share the existing operational boundary. The Engine keeps lesson generation, prompt assembly and validation, and the current private gRPC contract. W4 uses the existing Go and Engine stream for inference and can offload session coordination and fan-out without duplicating prompts, provider routes or the financial path. Each workstream has an independent rollback to the origin or current provider path.

Cloudflare documentation checked on 2026-11-24. The described vendor APIs and free limits are documentation facts. Local fakes and conformance tests establish application behavior. Account-specific limits and live service compatibility need evidence at a separately authorized release gate.

Cloudflare's changelog says inference stopped on 2026-11-20 with HTTP `410` and code `5028`, and points to `@cf/deepgram/aura-2-en`. ### Timing and storage

1. Decode bounded MP3 bytes and compute the playable duration from decoded samples and sample rate. Reject empty, corrupt, non-finite or out-of-bounds duration through the existing synthesis validation. Apply the same check to each pinned dialogue segment if a supported provider begins serving segmented synthesis.
2. Use the exact text represented by the existing alignment contract. Segment it into Unicode grapheme clusters for timing, weight each visible cluster by one and whitespace by zero, and keep punctuation in the alignment. For total weight `W`, decoded duration `D` and cumulative weight `w`, integer endpoints are `floor(D × w / W)` with the last endpoint set to `D`. Reject an empty/all-whitespace alignment input. Expand clusters into the existing character indexing by assigning the same interval to constituent characters, then validate monotonic start/end arrays and full text coverage. Use decoded cumulative segment offsets if synthesizing multiple segments. Track timing source as `estimated` or `vendor` in asset metadata and telemetry.
3. Keep the current alignment/object contract and one media clock for audio, caption highlights and Slide checkpoints. The final frame holds until audio ends. Pause, seek, replay, speed, mute, explicit Play and offline behavior follow the Lesson player requirements. Missing or invalid audio leaves the transcript and captions available. Estimated timing offers proportional highlights, with no claim of measured word boundaries.
4. Before each provider attempt, look up a versioned hash of NFC/whitespace-normalized text, provider, model, resolved voice, settings and timing algorithm version. Use the existing concurrent single-synthesis mechanism for each hash. A fallback resolves its own identity and checks its cache before spending. Persist and reference the successful asset under the actual provider/model hash. Keep existing asset keys readable, reference-counted and restoreable. Include existing cache keys for previously delivered audio on replay and recovery.

### Budget, pricing and evaluation

- Workers AI Free provides 10,000 neurons per account per day, reset at 00:00 UTC. At the published rates that is roughly 3,667 Aura-2 or 7,333 Aura-1 input characters a day before reserve headroom, retries and other account usage. A 1,440-character lesson means roughly 2–3 Aura-2 or 5 Aura-1 lessons' worth of characters. Paid usage above the allocation is $0.011 per 1,000 neurons with Workers Paid. The Free plan rejects further operations when the quota is exhausted. [Workers AI pricing](https://developers.cloudflare.com/workers-ai/platform/pricing/).
- Atomically reserve worst-case billable input neurons per authorized attempt in the existing durable budget accounting, with conservative rounding and a UTC-day bucket shared by processes and models. Cap the budget at the configured free allocation less headroom for other account usage. Compare aggregates with Cloudflare usage and lower or suspend the local budget if shared usage leaves insufficient headroom. Count uncertain submitted attempts at their bound, release unused reservations, and record actual billable use where known. Cache hits, disabled narration and unsupported-language skips need no vendor reservation. Keep the separate ElevenLabs character budget, Price version cost envelope and cancellation handling across all attempts. Treat invalid credentials, retired models and quota exhaustion as non-retryable on that route. Limit the combined vendor calls to the existing deadline and approved two-attempt bound. With `workers_ai` selected, try Workers AI then eligible ElevenLabs within its budget, then captions only. Release undelivered learner audio reservations. Stored, shared and restored audio retains zero-credit replay.
- Approval goes through the [Pricing config workflow](../pricing-config/design.md) and [governance capability](../../specs/pricing-config/spec.md). Use the existing `pricing_versions`/`pricing_audit`, valid cost policy (`services/api/internal/pricing/quotes.go`), and the admin draft → validate/diff → submit → approve → schedule process. Record the approved vendor/model billing basis in the quote policy with a conservative ceiling that covers the fallback and the estimated combined attempt cost. Historical versions and reservations keep their bound policy. `engine/config/prices.toml` is the Engine's model token cost table. The authoritative audio policy lives in the approved Postgres snapshots, seeded through API migrations such as `20261109054917_pricing_seed.sql`. Only vendor cost assumptions change. The learner-facing credit rate, settlement basis, packs, plans and entitlements stay as approved.
- Add `lesson_narration` Golden set cases for recorded successful English and Spanish MP3, multilingual/unsupported-language routing, deterministic alignment across accents/punctuation/non-Latin text, corrupt audio, concurrent dedup, exhaustion, vendor failure and captions-only settlement. Cover MeloTTS JSON/base64 and binary examples as historical contract fixtures only if used to exercise timing, and verify retired-model `410`/`5028` classification without live calls. Run offline fixtures with `mise run engine:eval`. Submit synthetic cases to the pinned Hugging Face dataset through the dataset owner and require applicable live promotion evidence per ADR 0019 before enabling a model on Learner traffic. See [evals README](../../../evals/README.md).

## W2. AI Gateway and OpenRouter

- `OPENROUTER_BASE_URL` defaults to `https://openrouter.ai/api/v1`. The documented provider base is `https://gateway.ai.cloudflare.com/v1/{account_id}/{gateway_id}/openrouter`, with `/chat/completions` appended. The Cloudflare page's curl example also uses `/openrouter/v1/chat/completions`. Follow its documented base and SDK example, and verify endpoint joining with a fake upstream and account-specific evidence before enabling. Authenticate separately with `cf-aig-authorization: Bearer <Cloudflare API token>` (AI Gateway Run permission for provider-native access) and `Authorization: Bearer <OpenRouter token>`. Use only existing OpenRouter credentials and disallow Unified Billing fallback. The alternate Cloudflare REST surface uses `Authorization` for Cloudflare credentials and a distinct provider-routing contract. [OpenRouter endpoint](https://developers.cloudflare.com/ai-gateway/usage/providers/openrouter/), [authenticated gateway](https://developers.cloudflare.com/ai-gateway/configuration/authentication/), [Gateway REST](https://developers.cloudflare.com/ai-gateway/usage/rest-api/), [provider credentials](https://developers.cloudflare.com/ai-gateway/configuration/manage-gateway/#prevent-unified-billing-fallback-for-byok-third-party-providers).
- Keep Gateway logs and default cache off globally. For any private, unclassified or STT request send `cf-aig-collect-log: false` and `cf-aig-skip-cache: true`. The payload-only logging header leaves metadata in logs and these request headers do not control Logpush. Keep Logpush and payload exports off. Permit caching only for server-identified, identical and non-personal requests for the shared demo or a public preview. The current authored demo already serves static data without a model call. If an eligible inference exists, use an exact equivalence key covering provider, endpoint, model, request parameters and version with `cf-aig-cache-key` to opt in and `cf-aig-cache-ttl` to set a TTL of 60 seconds to one month. Use the same privacy defaults on every new route. [Logging](https://developers.cloudflare.com/ai-gateway/observability/logging/), [caching headers and scope](https://developers.cloudflare.com/ai-gateway/features/caching/).
- Keep STT `provider.zdr=true` and `provider.data_collection="deny"` on every attempt. Test the existing OpenRouter `/audio/transcriptions` JSON contract, including base64 `input_audio`, with both routes. Cloudflare documents OpenRouter chat but gives no OpenRouter transcription guarantee on that provider page. Keep STT direct until the compatible Gateway path and its no-retention handling are verified with synthetic audio and environment configuration. Record no audio, transcript or request body in logs, caches, tracing or persistence. [OpenRouter STT routing](https://openrouter.ai/blog/tutorials/transcription-on-openrouter/), [ADR 0021](../../../docs/adr/0021-voice-input-data-handling.md), [AI Gateway ZDR scope](https://developers.cloudflare.com/ai-gateway/features/unified-billing/#zero-data-retention-zdr).
- Engine owns one bounded direct retry if the Gateway transport is unreachable or times out, or a transient Gateway failure occurs before valid output. Use sanitized HTTP/error classification, including Gateway `5xx` and Cloudflare `2005` (which can arrive as HTTP `400`). Respect caller cancellation and the deadline and reserve budget for each attempt. Enforce intentional rate/spend/security limits and ordinary provider validation or credential denials. A known unavailable Gateway configuration may be disabled by reverting the URL; never replay after any user-visible delta. Disable independent Gateway retry policy so attempts remain within the existing Engine envelope. Keep existing OpenRouter model fallback distinct from Gateway transport fallback. Ensure Gateway-only headers and secrets stay on the configured authenticated Cloudflare route and never follow redirects. [Request handling](https://developers.cloudflare.com/ai-gateway/configuration/request-handling/), [error behavior](https://developers.cloudflare.com/ai-gateway/reference/troubleshooting/).
- Core caching, analytics and rate limiting are free. Free accounts have 10 gateways, with 25 MB per cacheable request and at most one month TTL. The 200 requests/60 seconds limit applies to Cloudflare-managed Unified Billing credentials. Existing OpenRouter inference retains its provider pricing. Legacy Free log storage is 100,000 entries/account, and newer accounts follow Workers Logs (200,000/day, three days at the check date, with a documented 2026-12-01 pricing transition). [Pricing](https://developers.cloudflare.com/ai-gateway/reference/pricing/), [limits](https://developers.cloudflare.com/ai-gateway/reference/limits/), [Workers Logs](https://developers.cloudflare.com/workers/observability/logs/workers-logs/).

## W3. Public reads and bot protection

### Data access and conformance gate

- For eligible anonymous reads, use the Worker Hyperdrive binding over a TLS private Postgres connection through Cloudflare Tunnel and a Cloudflare Access Service Auth policy. `cloudflared` is outbound from Hetzner. The tunnel has a Cloudflare hostname protected by Access and a scoped service token. The Postgres listener stays private. Use a dedicated login role with `CONNECT`, schema `USAGE` and `SELECT` only on the reviewed public projections. Make the role non-owner with no inherited writer/admin privileges, default transactions read-only, and verify reads of base/private tables and writes fail. A versioned view or parameterized read projection can expose only data already returned by anonymous Go endpoints. Keep Go authorization and writes, including enrollment and moderation, on the existing path. [Hyperdrive Tunnel and Access](https://developers.cloudflare.com/hyperdrive/configuration/connect-to-private-database/), [Access service credentials](https://developers.cloudflare.com/cloudflare-one/access-controls/service-credentials/service-tokens/).
- Hyperdrive is on Workers Free with 100,000 queries per day (cached and uncached), ten configs per account and approximately 20 origin connections per config. Free queries reset at 00:00 UTC and fail on exhaustion. Access Free covers up to 50 users and Cloudflare documents a 50 service-token account limit. Only the Hyperdrive service, using a single scoped token, reaches the tunnel. [Hyperdrive pricing](https://developers.cloudflare.com/hyperdrive/platform/pricing/), [limits](https://developers.cloudflare.com/hyperdrive/platform/limits/), [Zero Trust plans](https://www.cloudflare.com/plans/zero-trust-services/), [account limits](https://developers.cloudflare.com/cloudflare-one/account-limits/).
- Exercise share preview (`GET /v1/public/shares/{token}`), Marketplace browse and public Course page (`GET /v1/marketplace/courses[/{id}]`), and authored shared demo (`GET /v1/courses/shared-demo`). Serve the authored demo from the same versioned fixture/objects as Go. Authenticated or cookie-bearing requests go to Go for viewer block and enrollment state. Keep `MARKETPLACE_ENABLED` default false and gate it before the cache. Share links retain `noindex`, neutral 404s, revocation/rotation, rate limits and viewer handling. Check Go's authoritative token visibility/revocation and Turnstile before each protected share preview response, including on cache hits. Link-gated bodies remain `no-store` to browsers and shared intermediaries. A validated anonymous projection may use an internal Worker cache keyed by a nonlogged protected token digest and immutable publication version. Never route anonymous database reads directly to base private data.
- Cache only reviewed anonymous-success projections with a bounded TTL. Key marketplace responses by normalized route, query, locale and schema/version. Exclude cookies, tokens, private/error responses, `Set-Cookie` and user-specific data. Use `MARKETPLACE_CACHE_TTL_SECONDS` for the marketplace listing/page cap and the existing authored shared demo max-age. Bound total stale time across layers from the origin read, disable Hyperdrive query caching for moderated or revocable reads, and prohibit stale revalidation beyond the cap. Go's immediate Redis invalidation stays in force. Revoke/rotate stops the next share open, and a moderation hide becomes invisible within the configured TTL or earlier if invalidation succeeds. Keep the Worker entry point out of any front-of-Worker caching for Turnstile routes. The Worker Cache API (`caches.default`) is local to a data center, so TTL remains the cross-location backstop. [Workers Cache API behavior](https://developers.cloudflare.com/workers/reference/how-the-cache-works/), [Hyperdrive query caching](https://developers.cloudflare.com/hyperdrive/concepts/query-caching/).
- Go's Marketplace and share-preview routes currently return `no-store` and `noindex`. Preserve those headers on delivered responses. The Go fallback can mark an allowlisted anonymous projection as eligible for the internal cache only on a trusted Worker-to-origin request, with its origin freshness bound. The Worker validates the opt-in, caches only the projected data under an internal key and reapplies the public-facing policy. Absent that opt-in it forwards without caching. Both read modes apply the origin rate-limit contract before returning a cache hit.
- Before selecting Hyperdrive, run the CF-03 `edge:test` conformance cases against a migrated disposable Postgres with the exact read-only role and deterministic seeded fixtures. Compare origin and Worker HTTP status, payload keys, ordering, cursor pagination, security/cache policy, visibility and neutral denials under anonymous, blocked-viewer, private, revoked, rotated, removed, moderated and flag-off cases. Warm caches, mutate state through Go and prove the freshness and authorization bounds with an injected clock. Verify the role can read only projections, then exercise connection/limit failures. Use the Hyperdrive local connection string with local workerd. That exercises query/result and role conformance. A separate authorized environment check covers the actual Tunnel/Access handshake, TLS and pooling before routing traffic. If conformance fails or the authorized environment cannot satisfy availability and isolation, select the Worker mode that edge-caches the existing Go public reads under the same rules. If edge cache conditions fail, forward uncached to Go. [Hyperdrive local development](https://developers.cloudflare.com/hyperdrive/configuration/local-development/).

### Turnstile

The client renders the Turnstile widget and sends a fresh proof for each protected action. In this checkout `POST /v1/auth/code` requests email codes and `POST /v1/auth/verify` is the combined verification and email sign-up path. Verify there before code consumption or account creation, without an account enumeration branch. Existing OAuth handoffs stay governed by their own provider verification. On `GET /v1/public/shares/{token}`, send proof in a header and keep tokens out of URLs and logs. The Worker either calls an authenticated Go verification endpoint before cache lookup or lets Go validate and serve the request on the origin path. The path must redeem the proof once. Failed, missing, expired or unavailable verification blocks the action and gives a safe retry state. Retain existing rate limits and OTP error semantics.

Email requests carry `turnstile_token` in JSON. Share reads use `X-Turnstile-Token`. Go expects the action `email_code`, `sign_up` or `share_preview` respectively and returns HTTP 400 with `code=turnstile_failed` when verification fails. `GET /v1/auth/turnstile/config` returns the public enabled flag and site key so web and native clients use the API's rollout state. The share handler uses `VerifyPreviewProof` after the rate limit and before reading the preview. CF-03 can reuse that seam on an authenticated origin verification path.

Go posts to `https://challenges.cloudflare.com/turnstile/v0/siteverify` with `secret` and `response` in JSON or form encoding, optional `remoteip` and `idempotency_key`. Use trusted origin information, validate `success`, expected `hostname` and `action`, and permit one bounded idempotent retry for transport errors. Tokens have a 300-second lifetime and are single-use. Cloudflare documents network convergence limits, so keep application actions independently idempotent. Test keys work on localhost. The documented dummy response uses hostname `example.com` and omits `action`, so test hostname/action failures with fake responses while production checks stay strict. [Siteverify contract](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/), [official dummy keys](https://developers.cloudflare.com/turnstile/troubleshooting/testing/).

| Test outcome | Visible sitekey | Secret key |
|---|---|---|
| Always pass | `1x00000000000000000000AA` | `1x0000000000000000000000000000000AA` |
| Always fail | `2x00000000000000000000AB` | `2x0000000000000000000000000000000AA` |
| Already spent | `1x00000000000000000000AA` | `3x0000000000000000000000000000000AA` |

Turnstile Free supports 20 widgets, 10 hostnames per widget and unlimited challenge/verification traffic. Use a configured hostname list. Production keys are environment secrets and the sitekey is public. [Turnstile plans](https://developers.cloudflare.com/turnstile/plans/).

## W4. Chat sessions at the edge

- `CHAT_EDGE_ENABLED=false` by default. Both server and client honor the server capability. Use an authenticated Go-authorized, short-lived channel credential bound to the Learner session, scope and thread, with Origin validation, expiry and revocation. Keep credentials out of URLs and logs. Derive the Durable Object name in the Worker from verified claims and bind every request and reconnection to the same session. The Worker sends a separate, scoped service credential over TLS to Go. Go checks service identity and learner/thread authorization for each operation, including stop and resume. Clients cannot reach the DO or financial adapters directly by guessing identifiers.
- Use SQLite-backed Durable Objects and the Agents SDK from `agents`. `Agent<Env>` with `routeAgentRequest`, `onConnect`, `onMessage`, `onClose`, and `onRequest` supplies the session class and HTTP fallback. The documented `AIChatAgent` in `@cloudflare/ai-chat` automatically persists messages to SQLite. Use the base `Agent` with Duolify's protocol and transient connection metadata so Postgres stays authoritative and learner content is excluded from DO storage, attachments and replay logs. `AgentClient` or `useAgent` can connect over the SDK's default hibernating WebSocket. Underlying DO hibernation uses `ctx.acceptWebSocket`, `webSocketMessage`, `webSocketClose` and `serializeAttachment`/`deserializeAttachment`. Keep only opaque, expiring connection metadata in attachments and recover acknowledged turn state from Go after a wake. The `onRequest` SSE fallback returns a `ReadableStream`, `Content-Type: text/event-stream`, event IDs and heartbeats at most 25 seconds apart. Reconnect by stable turn/event ID against the Go record. Use ordinary SSE streaming rather than storing messages or chunks in the SDK's experimental `Streams` capability. [Agents base class](https://developers.cloudflare.com/agents/agent-class/), [chat agent persistence](https://developers.cloudflare.com/agents/agent-class/communication-channels/chat/chat-agents/), [Agents WebSockets](https://developers.cloudflare.com/agents/runtime/capabilities/websockets/), [DO hibernation API](https://developers.cloudflare.com/durable-objects/best-practices/websockets/), [Agents SSE](https://developers.cloudflare.com/agents/runtime/routing/http-sse/).
- Use Go for quote, explicit accept, idempotent reserve, settle or release, and chat persistence. Bind the client turn ID to the existing quote and idempotency record in Postgres. Serialize starts by the canonical operation key, reconcile actual usage and commit terminal state in Go. A reconnect or ambiguous response first resolves the canonical turn before switching transports. Never restart a model call after a delivered delta, duplicate a reservation, or charge twice. Retain cancellation, timeout, received partial replies and typed failures. The client steps down from WebSocket to Edge SSE, then the existing Go/Engine path on eligible transport failure. The Engine path can handle fresh turns when edge availability or the flag changes. Consumed resume cursors or an interrupted turn show the existing recovery state instead of replaying work.
- Guided chat keeps scripts, deterministic commands, consent, offline answers, secret handling and free FAQ behavior. Edge transports carry only network-backed intent or guide/tutor operations that already need the API. Scripted flows retain the configured deterministic fallback when the classifier fails, and chargeable questions still require the Action quote. The browser e2e covers both transports, paid turns with one settlement, guided flow behavior, relaunch, stop, fallback to the Engine and opt-out/disabled cases.
- SQLite-backed DOs are on Workers Free. Free DO limits include 100,000 requests/day, 13,000 GB-s duration/day, five million SQL reads/day, 100,000 writes/day, 1 GB per object and 5 GB combined. Hibernating idle WebSockets avoid idle duration charges. Active DO wall time can still count toward duration even though network waits are distinct from CPU. Workers Free ingress separately has 100,000 requests/day and 10 ms CPU per HTTP request. Keep Edge work small, measure the quotas independently and fall back to Go within free limits. [DO pricing](https://developers.cloudflare.com/durable-objects/platform/pricing/), [DO limits](https://developers.cloudflare.com/durable-objects/platform/limits/), [Workers limits](https://developers.cloudflare.com/workers/platform/limits/).
