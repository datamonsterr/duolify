# ADR 0011: Owner decisions for the E1–E17 breakdown

- Status: Accepted (owner, 2026-11-09)
- Date: 2026-11-09

## Context

The ticket breakdown (`docs/epics/tickets.md`) found decision tickets that blocked most implementation work. The owner answered them on 2026-11-09. Values that live in the Pricing config stay changeable by a new config version.

## Decisions

| Ticket | Decision |

| E6-05 | A shared Friend-streak day is each friend's own local date; it counts when both complete a Lesson on their own local date and those dates overlap in real time. Each friend sees their own local date; rollover is decided by the later day-end (spec rule). |

## Defaults chosen during implementation (pending owner review)

- E5-01: Gamification config seeds 10 base XP, a 5 XP first-try-perfect bonus, daily goals of 10/20/30/50 XP and a 20 XP default. Existing profile goals remain readable; new goal selections use configured choices. Legacy completion summaries receive base XP without an inferred perfect bonus. XP retains its completion-local date/timezone at consumption and survives Course deletion until account deletion. No effort rewards grant Credits.
- E3 review (#164): Offline download entitlement gates the authenticated library listing and bulk download convenience. Per-lesson manifest and slide delivery require enrollment only, including after subscription expiry; already-delivered playback is never revoked. Bulk downloads temporarily use 50 lessons / 100 MiB and restore the normal five lessons / 16 MiB bounds on success, failure, or cancellation. Playback sync keys are unique per learner; valid events are acknowledged independently and invalid events are permanently rejected. Advisory timestamps clamp to 2000-01-01 UTC through server time plus two minutes.
- E3 containment (#164/#165 bridge): The opaque-origin iframe sandbox (`allow-scripts` only) and restrictive CSP are the primary boundary, independent of the HTML regex validator. Keep `base-uri` / `form-action` denied and request `navigate-to 'none'` as additional defense where implemented; browsers may ignore that directive. No top navigation, same-origin, or popup sandbox permissions are granted. Dynamic documents use an empty network origin; prepared documents and offline indexes belong to the current account and clear on logout.

- E17-05 (pinned Course Casts in generated Lessons): The Cast is pinned in the job-start transaction under the `lesson_generations` id and reused by worker retries and Retry variants; Course preview uses the default Cast, since no Course exists yet to carry a selection. Unusable selected slots fall back per slot to the default of the same role (`fallback_used`). Segments allow at most 12 per Slide, 280 plain-text characters each, inside the Slide clock; text containing markup, `{}`, backticks, control characters or URL/data/asset patterns is rejected. Attempt 1 uses the persona prompt; the single allowed fallback attempt regenerates with a neutral default persona, so the E10-03 two-attempt, quote, deadline, token and USD caps are unchanged. An invalid base Lesson or segment set fails the job and releases the reservation. Generated slides render a host-clocked stage (no iframe timers); unsupported rigs, invalid specs or unknown speakers use bundled defaults at render time without mutating the stored Cast. Offline eval cases require 1.0 for persona, injection and snapshot gates; live promotion stays disabled until E10-06 evidence.
- E17-06 (reactions to authoritative answers): The API maps the graded result to a deterministic reaction (`answer_correct`/`happy`, `test_passed`/`celebrate`, `answer_incorrect`/`thinking` with a queued Retry variant else `sad`; idle is the static neutral expression) and stores it inside the existing answer-operation payload, so replays and restored attempts are identical. Copy is one of three approved supportive lines; persona text, names and response strings are never shown. The reaction is display-only and never read by grading, mastery, Retry, XP, unlock or completion code. Unusable Cast, rig, spec or reaction falls back to the bundled neutral SVG with correction and Continue intact. `character_reaction_shown` is emitted by the client once per result with closed enums only. No proto, table, migration, runtime model call or spend is added; `character_reactions` offline cases gate at 1.0 and live promotion stays disabled until E10-06.
