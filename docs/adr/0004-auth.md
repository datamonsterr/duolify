# ADR 0004: First-party auth in the API

- Status: Proposed (confirm) — truly ambiguous
- Date: 2026-11-08

## Context

Clients are Tauri desktop and mobile apps. Options: hosted provider (Clerk, Supabase Auth, WorkOS) or first-party.

## Decision

First-party auth in `services/api`: email one-time code sign-in first, then OAuth (Google, Apple) via the system browser and deep link. Short-lived JWT access token (15 min) plus rotating refresh token stored hashed in Postgres. Tokens stored on device in the OS keychain (Tauri `stronghold` or keyring plugin).

## Why

No per-user vendor cost, no vendor lock-in for a learning app with many free users, one less service for Railway.

## Consequences

- We own security-critical code: rate limits on code requests, token rotation, revocation.
- Bootstrap ships a dev-only stub login. Real auth is its own OpenSpec change.
