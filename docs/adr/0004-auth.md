# ADR 0004: First-party auth in the API

- Status: Accepted (owner, 2026-11-09; see ADR 0011): OTP mail via Resend, tokens via the Tauri keyring plugin. The OAuth part (Google, Apple) is superseded by ADR 0016 (Clerk for SSO); email codes, Duolify sessions and rotation stand.
- Date: 2026-11-08

## Context

Clients are Tauri desktop and mobile apps. Options: hosted provider (Clerk, Supabase Auth, WorkOS) or first-party.

## Decision

First-party auth in `services/api`: email one-time code sign-in first, then OAuth (Google, Apple) via the system browser and deep link. Short-lived JWT access token (15 min) plus rotating refresh token stored hashed in Postgres. Tokens stored on device in the OS keychain (Tauri `stronghold` or keyring plugin).

## Why

No per-user vendor cost, no vendor lock-in for a learning app with many free users, one less service for Railway.

## Consequences

- We own security-critical code: rate limits on code requests, token rotation, revocation.
- Bootstrap ships a dev-only stub login. Real auth is its own OpenSpec change.

## Amendment (2026-11-22): web session storage

ADR 0004 stored tokens in the OS keychain for the Tauri apps and said nothing about browsers. ADR 0011 (E1-163) then fixed the browser fallback as in-memory only, with no Web Storage, to keep tokens out of script-readable storage. That left the web build signed out by every full page load.

The intent stays and the decision is refined, so this is an amendment and not a new ADR:

- The **access token** stays in memory only in the browser.
- The **refresh credential** for the web build is held by the browser as an `HttpOnly`, `Secure`, `SameSite=Strict` cookie (`duolify_refresh`, `Path=/v1/auth/`, host-only), set and read by the API for clients that send `X-Duolify-Client: web`. Script cannot read it and it is never stored in `localStorage` or `sessionStorage`. On start the web client calls `POST /v1/auth/refresh` to get a new access token.
- Native (Tauri) clients keep the body and keychain flow unchanged, and the server never sets the cookie for them.
- Rotation, reuse detection, the 5-second grace and revocation are unchanged. Cookie requests also need a same-origin `Sec-Fetch-Site` and an exact configured `Origin`.

Details and threat notes: `openspec/changes/persist-web-session/design.md`.
